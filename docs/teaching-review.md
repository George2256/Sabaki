# 教学讲解：设计与使用

本功能在右侧栏增加独立的「教学讲解」页签。原有胜率图、棋树和棋谱评论保留；讲解结果不自动写入 SGF，不改变当前分支，不覆盖用户注释。

## 使用方法

1. 打开棋谱，并选定要复盘的分支。
2. 在「工具 → 教学讲解」打开右侧页签。尚无 KataGo 时，点「准备 KataGo」使用已有自动安装入口。
3. 选择引擎、规则、学员棋力与搜索预算；「使用棋谱规则」要求 SGF 有可识别的
   `RU`。点「讲解当前分支」。
4. 等待扫描与复查，先阅读卡片中的讲解，点击文字下的引用跳到对应变化步骤，再查看实战图、推荐图、惩罚图。好棋卡片用较差候选的「对照图」代替惩罚图。「定位这手」将主棋盘移到对应实战节点。
5. 可选展开「LLM 讲解」，填写完整 Chat
   completions 端点、模型和密钥，点「应用连接」，勾选发送证据后重新讲解。默认使用棋盘事实讲解；连接设置和密钥仅留在当前窗口会话。

切回「棋谱」页签继续查看棋树和评论；教学结果仍保留。修改落子、规则、贴目、摆子或切换分支会使结果失效。同一分支内浏览和修改评论不会使结果失效。

教学标题右侧的「×」关闭板块并停止当前任务，随后恢复原右栏布局；已生成结果在重新打开时仍可查看。引擎正在落子或执行其他命令时，等待其完成后再开始教学。

## 目标与证据边界

针对当前选定分支寻找坏棋、好棋和关键转折，展示实战图、推荐图和惩罚图。推荐与惩罚变化必须来自 KataGo；讲解引用结构化证据 ID，不能自行产生落子序列。胜率和目差是有限搜索下的估计，不是数学证明。没有足够访问数、合法变化或稳定比较结果时，应说明证据不足。厚薄、轻重、方向等解释只能标为教学推断。

## 仓库基础与架构决定

- `src/modules/sabaki.js` 管理棋树、导航、GTP 引擎及现有快速分析。
- `src/modules/gametree.js` 重建棋盘，`src/modules/fileformats/sgf.js`
  解析 SGF。
- `src/modules/enginesyncer.js` 与 `analysis.js` 提供交互式 GTP 分析。
- `src/components/Sidebar.js` 组合胜率图、棋树和评论。
- 自动安装的 KataGo 运行时由 `src/engine-setup.js` 管理。

教学任务采用独立的 KataGo Analysis Engine
JSON 进程。扫描与深查使用同一协议，便于保留完整规则、落子历史、访问数和 PV。现有快速绘制胜率图继续使用 GTP。教学开始前结束快速分析和连续分析；引擎对弈期间不开始教学。教学运行时禁用「快速绘制」，菜单、F6 和直接调用也不会中断教学；需先手动停止教学再绘图。其他引擎任务启动时仍取消教学并等待其释放资源，避免两个任务竞争 GPU 或串用命令。

教学服务属于当前窗口，进度只返回发起窗口。关闭窗口、取消任务或编辑棋局会终止相应任务；请求 ID 与局面指纹用于屏蔽过期结果。浏览同一分支的节点可以继续。

## 模块与数据流

1. Renderer 从当前分支生成不可变快照：节点 ID、原始颜色与坐标、初始摆子、棋盘尺寸、贴目、规则、行棋方；不发送姓名、赛事或原有评论。
2. Main 服务通过受限 IPC 接收快照，运行私有 KataGo JSON 分析进程。
3. 扫描各手前后局面，筛选影响大、胜负临界和具有替代着法比较价值的节点。
4. 对入选节点以更高预算复查，并对实战着法补足搜索；推荐图来自着前 PV，惩罚图来自实战落子后对手的 PV。逐手重放，检查坐标、颜色、提子与合法性。
5. 生成带规则、模型、预算、访问数和起点信息的证据。默认由模板生成讲解。
6. 可选的 LLM 只接收这些证据，返回证据 ID 引用和讲解文本。程序拒绝未知引用、未验证坐标或未经授权的变化；失败时保留可用的模板讲解。
7. 右侧教学页签显示进度、节点卡片与三个可逐手查看的独立棋盘。

内部胜率统一为黑方概率
`[0,1]`，目差统一为黑方目差。判断落子损失时换算为落子方视角。候选的胜率、目差和 PV 必须来自同一个 moveInfo，不能分别取最大值。

位置指纹包含分支落子历史、摆子、行棋方、规则、尺寸和贴目；只有棋盘图案相同不足以复用劫争结果。初始版本不支持中途摆子/删除棋子和超过 19 路的棋盘。未知规则需要由用户选定规则，不能默默按 Tromp–Taylor 规则分析。

### 接口约定

`window.sabaki.teaching` 提供
`status()`、`configure({endpoint, model, token})`、`start({position, engineIndex, budget, useLLM, language})`、`cancel()`
和 `onChange(callback)`。请求返回 `{ok, data}` 或 `{ok:false, error}`；进度包含
`jobId/fingerprint/rootId/phase/running/completed/total/cards/skipped`。引擎索引从主进程的
`engines.list` 解析，不接收 Renderer 任意指定的可执行命令。

快照字段为
`rootId/boardXSize/boardYSize/komi/rules/initialPlayer/initialStones/moves/anchors`；每手明确携带
`[B|W, GTP坐标|pass]`，每个 anchor 保留实战节点与着前节点。教学服务复制快照后启动；结果只在指纹一致时附着到界面。

KataGo 每次请求包含完整落子历史、起始摆子、规则、贴目、`analyzeTurns:[turn]`、`maxVisits`、`analysisPVLen`
和 `ignorePreRootHistory:false`。比较实战着法使用 `allowMoves`
限制根节点第一手，补足低访问候选的搜索。解析器按请求 ID 与 turn 收最终结果，丢弃搜索中间报告。规则警告、错误或缺失数据不能当作验证成功。

每张卡片保存推荐与实战着法的评价、访问数、请求 ID、两个预算下的损失、模型版本与 SHA-256，以及每条图的来源请求与重放请求 ID。实战图是真实棋谱续着，不称为引擎推荐。

LLM 返回
`{lessonId, paragraphs:[{text,refs:[{diagramId,step}],factIds}]}`，没有添加或替换变化的接口。每段必须引用合法图的具体步骤和匹配的棋盘事实。步骤 0 对应起点棋盘。不存在的图、越界步骤、不匹配的事实、虚构坐标、错误的黑白编号、HTML 和数字目差/胜率会被拒绝；允许既有坐标、正确步号及“先补一手”等自然表达。输出格式或引用失败时重试一次，连接错误不重试；仍失败则保留本地讲解并显示原因。数值比较移入可展开的分析证据。自由文字的语义不能仅靠 ID 引用证明，因此额外文字始终显示为「教学推断（LLM）」，不作为死活、先手或最佳性的证据。

## 棋力、棋盘事实和讲解结构

分析前可选刚入门、20/15/10/5/1 级、1/3/5 段。棋力是自我评估的教学参考，不承诺不同平台段级位等价，也不降低 KataGo 的计算棋力。基础学员优先获得气与连接的具体问题；级位学员关注攻防、次序和读棋；段位学员增加交换价值与全局机会成本。变更棋力不会丢弃相同局面的扫描和深查缓存。

`facts.js`
从棋盘重放提取着前棋块、每块的棋子与气，以及每一步的提子、连接、打吃、从一气逃出和原棋块气的变化。实战图保留
`source:sgf`、`verified:false`，同时标记
`legal:true`；因此可进入讲解上下文而不会被误称为引擎推荐。

本地讲解比较第一手对同一目标棋块的作用，再选择附近相关的对手应对，最后给符合棋力的读棋问题。远处的一气棋子可能是弃子，不能一概说成当前必须救的棋。已有短变化不能确认战略原因时，会说明不足并给出具体练习，不根据目差编造因果。

LLM 输入包含这些事实、真实续着、搜索得到的对照变化、学员层级和少量讲解结构参考。讲解要求串起当前问题、实战遗漏、对手利用、推荐作用和下次检查方法，根据局面调整内容，不机械重复固定段落。自由文字仍可能误读棋形；引用校验只能检查来源和格式，不能证明战略推断。当前没有归属图、死活证明或先手证明查询。

24 个结构样例来自安永吉八段对李世石—AlphaGo 第一局的公开评注，保留手数和出处。结构摘要与原棋谱遵循 CC
BY-NC-SA 4.0，和 MIT 程序代码分开，详见
[样例说明](../src/teaching/reference-library/README.md)。它们只示范如何解释，不是现代引擎结论，更不是已获得教师评分的验收答案。初始集集中于一盘职业棋局；低段棋例、教师人工评分、真实语言模型效果评价仍需扩充。

## 筛选方法

快速扫描仅用于提名，不直接给出最终等级。深查用同一搜索预算比较推荐与实战。坏棋以目差损失为主，胜率损失为辅；胜率接近 0 或 1 时不放大微小波动。好棋需要实战接近推荐，并且有经过搜索的明显较差替代着法。转折需要深查前后胜负判断变化。访问不足、差异不稳定或低于阈值时不作强结论。

MVP 具体阈值：按落子方目损、胜率百分点和越过 50% 排优先级；候选间隔至少五手，最多五个。间隔只减少连续重复，尚未做空间聚类。推荐与实战各用深查预算及其两倍预算分析，四次候选访问数都需至少 80。两次损失差超过
`max(1目,最终目损的50%)` 或 `max(5个百分点,最终胜率损失的50%)` 时不作稳定判断。

- 坏棋：目损至少 2，或胜率损失至少 8 个百分点且目损至少 0.5。
- 转折：稳定的坏棋，深查比较跨过 50% 且胜率损失至少 8 个百分点。
- 疑问手：达到坏棋阈值，但两个预算下结果不稳定。
- 好棋：实战距推荐不超过 0.7 目、3 个百分点，并有强制搜索后至少差 2 目的替代候选。替代着法和对手回应也要求至少 80 次访问。

KataGo 会容忍输入历史中的部分非法着法，终点分析不足以证明序列合法。所有最终变化先本地重放，然后逐手携完整历史查询着前局面的
`includePolicy`；拟下着法必须在 KataGo 的合法着法掩码中不是
`-1`，最后再分析终点。这样验证劫与超级劫，不依赖引擎容忍的历史输入。空 PV 或非法变化不展示。PV 是有限搜索的主变化；合法性检查不等于逐手证明全局最优。

## 展示与状态

界面文案只保留标题、操作、实际状态和具体局面结论，不复述开发目标，也不在每张卡片重复通用教学引导。分析来源与验证过程放在可展开的「分析证据」中。

右栏页签为「棋谱」和「教学讲解」。棋谱页保留原布局；教学页保留上方胜率图，其下显示自己的内容。通过工具菜单进入，即使原右栏隐藏也能打开教学。三图不使用评论中正则识别的坐标串，不触发原棋盘的落子、编辑和引擎同步。点击「定位这手」才导航到实战节点。原有评论编辑时保持棋谱页，输入不丢失。教学不会写入
`C/N/TE/BM/SBKV/SBKS` 或新增 SGF 分支。

## 性能、隐私与恢复

默认串行扫描，关键节点再深查；限制总节点数和变化长度。扫描也检查实战每步合法性；三图逐手校验增加若干低预算查询。分析进程超时、退出或输出错误时停止并保留已完成卡片。取消会终止进程、等待退出并清理监听。

| 预算 | 每局面扫描访问上限 / 时间 | 首次深查访问上限 / 时间 | 确认深查访问上限 / 时间 |
| ---- | ------------------------- | ----------------------- | ----------------------- |
| 快速 | 100 / 1秒                 | 400 / 2秒               | 800 / 4秒               |
| 标准 | 150 / 1秒                 | 800 / 4秒               | 1600 / 8秒              |
| 深入 | 250 / 1秒                 | 1600 / 8秒              | 3200 / 16秒             |

预算是上限，实际访问数受硬件和模型影响。冷启动可能达不到证据最低访问数，界面会跳过该节点。每次分析进程启动都会载入模型并计算模型文件哈希；全盘扫描通常需要数分钟。目前只在单窗口内与原分析/对弈互斥，多个窗口仍可能竞争 GPU。私有配置不会继承原 GTP 的全部设备与调优参数，Windows、Linux 和不同 GPU 尚需实际环境验证。

LLM 默认关闭。启用时由用户配置端点和模型，只有明确点击生成任务才发送证据、着前棋盘和已验证图；不发送 SGF 评论、姓名、路径或模型文件，也不发送自定义引擎名称。应用连接后立即清空 Renderer 密钥字段，仅留在主进程当前窗口会话，不进入持久化设置。每张卡片最多两次 LLM 请求（含一次校验重试），每次上限 1500 输出 token；最多五张卡片；输入长度取决于棋盘和变化，费用由所选服务决定。连接与输出校验失败时保留棋盘事实讲解。自由文字可能有错误，不能取代引擎比较证据。

教学在当前窗口保留最近一次任务的完整扫描结果，以及最多 2048 个分析请求结果。停止后点「继续讲解当前分支」，从首个未完成局面续扫；深查和变化验证也复用已完成的请求。完整讲解再次启动时同样复用。只有完整分支快照（历史、摆子、行棋方、规则、棋盘尺寸、贴目和节点定位）、引擎路径与参数、版本、主模型及可选 HumanSL 模型的内容哈希、私有配置和搜索预算全部一致时才复用；不一致则重新分析并替换缓存。浏览同一分支、改评论和绘制胜率图不会使缓存失效。语言或学员棋力切换复用数值证据，并重新筛选节点和生成讲解；LLM 文本不缓存，勾选发送后再次讲解仍会调用端点。

快速绘制的 `SBKV/SBKS`
不包含候选着法、访问数、模型来源和合法性证据，不能替代教学扫描，也不进入教学缓存。缓存命中仍需启动引擎并核对模型身份；被中断的请求不缓存。界面显示准备阶段与已复用结果数量。

棋谱不包含教学服务的持久化结果。关闭窗口后结果和缓存丢失；保存原 SGF 不会保存教学卡片。当前未实现持久化缓存、SGF 导出、HumanSL 候选和空间聚类。学员棋力已用于讲解与基础节点优先级，但尚未用于 HumanSL 着法生成。

## 后续增强

1. 将窗口内证据缓存扩展为持久化缓存，支持关闭窗口后继续，并保留完整失效检查。
2. 可选择把已验证变化和模板注释导出到新 SGF，预览差异后写入，不修改原文件。
3. 以 HumanSL 和棋力级别提名「自然但较差」的候选，再由主模型搜索验证；加入局部空间聚类，避免同一战斗重复讲解。
4. 对死活、先手、厚薄等具体解释建立可执行的检验问题；只有得到相应证据后才允许升级为事实句。LLM 自由文字继续保持推断标签。
5. 跨窗口 GPU 调度、配置继承白名单、设备基准与搜索置信度，扩展平台测试和超长棋谱性能验证。

## 实施步骤与验收

1. 设计、用户文档和进度日志；确定界面位置与任务互斥。
